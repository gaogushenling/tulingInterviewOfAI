## <font style="color:rgb(36,91,219);">1 </font>**概念辨析：Prompting、Prompt ****tuning****还有Prompt Learning**
| Prompting，指的是给语言模型输入一段特定的文本（即提示词），从而引导模型去生成特定的我们想要的输出文本。_<font style="background-color:rgba(183,237,177,0.8);">他其实就类似我们在</font>__<font style="background-color:rgba(183,237,177,0.8);">ChatGPT</font>__<font style="background-color:rgba(183,237,177,0.8);">里打字的过程啦。</font>_ |
| :--- |


| **<font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">Prompting refers to the process of giving a specific prompt or input text to a language model to guide its generation of a specific output text.</font>**<font style="color:rgb(143,149,158);"> The prompt text can be in the form of a question, a sentence, or a few words that are related to the desired output. The language model then generates the output text based on the prompt and its own internal understanding of the language.</font><br/><font style="color:rgb(143,149,158);">In other words, Prompting is a technique used to guide the generation of specific output text using a language model, while Prompt </font><font style="color:rgb(143,149,158);">Tuning</font><font style="color:rgb(143,149,158);"> is a technique used to adapt a pre-trained language model to a specific downstream task by fine-tuning it on task-specific data using prompts.</font> |
| :--- |


| Prompting Tuning（提示微调），和微调会更接近，是自动化生成“软提示”的一种方法。具体怎么work后面会介绍，_<font style="background-color:rgba(254,212,164,0.8);">不过在这里我们只需知道，Prompt tuning是微调的一种特殊形式，它是会改变模型的权重参数的，但它又比fine-tuning参数高效得多。</font>_ |
| :--- |


| **<font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">"Prompt </font>****<font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">tuning</font>****<font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">", a simple yet effective mechanism for learning "soft prompts" to condition frozen language models to perform specific downstream tasks. </font>**<font style="color:rgb(143,149,158);">Unlike the discrete text prompts used by GPT-3, soft prompts are learned through backpropagation and can be tuned to incorporate signal from any number of labeled examples. ——</font>[<font style="color:rgb(36,91,219);">The Power of Scale for Parameter-Efficient Prompt Tuning</font>](https://arxiv.org/abs/2104.08691) |
| :--- |


| <font style="background-color:rgba(255,246,122,0.8);">先用一个高亮块快速讲清楚提示学习的定义：</font><br/><font style="background-color:rgba(255,246,122,0.8);">再用这个高亮块快速讲清楚Prompt Learning</font><font style="background-color:rgba(255,246,122,0.8);">范式</font><font style="background-color:rgba(255,246,122,0.8);">的运作原理：</font><br/>**传统的预训练+微调**：预训练完后，利用有标签的下游数据集对模型做微调，这需要改变模型的权重与偏置参数。而后，基于下游任务输入x，模型预测输出y: P(y|x)。<br/>**新****范式****预训练+Prompt+Predict**：基于输入x，根据模版（Template）将其转为特定的结构化提示x'，x'是一个具有一定格式但是不完整的句子，有一些字段还没有被填充。对于x'，模型会基于概率对其进行填充，得到完整的输入。基于这个，模型再预测输出y。 |
| :--- |


| <font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">Prompt learning is a general term that refers to the use of prompts in </font><font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">machine learning</font><font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">. </font><font style="color:rgb(143,149,158);"> In the context of </font><font style="color:rgb(143,149,158);">natural language processing</font><font style="color:rgb(143,149,158);">, prompt learning involves training a language model to understand and respond to a specific set of prompts. </font> |

最后再额外提一嘴Prompt Engineering。<font style="background-color:rgba(255,246,122,0.8);">语言的发展经历了四个</font><font style="background-color:rgba(255,246,122,0.8);">范式</font><font style="background-color:rgba(255,246,122,0.8);">：基于符号主义的全</font><font style="background-color:rgba(255,246,122,0.8);">监督学习</font><font style="background-color:rgba(255,246,122,0.8);">时代、基于</font><font style="background-color:rgba(255,246,122,0.8);">神经网络</font><font style="background-color:rgba(255,246,122,0.8);">的全监督学习时代、预训练+微调阶段和预训练+提示词+预测阶段，这四个阶段分别对应了四类工程：</font><font style="background-color:rgba(255,246,122,0.8);">特征工程</font><font style="background-color:rgba(255,246,122,0.8);">（手动提取特征）、结构工程（搭建更好的神经网络结构以更好的提取特征）、目标工程（选取好的目标函数）和提示工程</font>。**<font style="background-color:rgba(186,206,253,0.7);">提示工程</font>**<font style="background-color:rgba(186,206,253,0.7);">，指的是精心去设计提示词Prompt，以让语言模型可以生成我们想要的输出，最大的发挥语言模型的潜力。</font>

## <font style="color:rgb(36,91,219);">2 </font>**开端：当我们发现一个模型做的越大越好之后……**
我们在12.2.2.4中提到了，GPT-2模型的参数量达到了15.42亿，尽管其性能还不够好，但它确实证明了不断地去堆参数，把模型做的更大，模型性能还是可以继续上去的。但模型变大了以后，其他的问题就接踵而至。首先，有如下两个问题：

+ 预训练的模型大，所需要的预训练语料（数据量）就多。<font style="background-color:rgba(255,246,122,0.8);">无监督预训练用的数据量多了，那么下游预训练的有标注数据相比之下就微不足道了。</font>
+ 预训练的模型大，参数量多，用反向传播算一次梯度的成本剧增。<font style="background-color:rgba(255,246,122,0.8);">微调变得又贵又不可能。</font>
+ 此外，<font style="background-color:rgba(255,246,122,0.8);">Fine-tuning毕竟是要基于有监督下游任务改变模型的Weights & biases的，所以很容易</font><font style="background-color:rgba(255,246,122,0.8);">过拟合</font>。

| <font style="background-color:rgba(251,191,188,0.8);">我们知道，GPT-2的模型参数为15亿，到了GPT-3就将达到1750亿个参数了</font>。如此骇人听闻的参数规模，好不容易花了巨大成本预训练完，你再对他去做梯度下降，算反向传播算法，哪怕只是针对少量下游任务数据的fine-tuning，这个成本也是我们难以承受的。<br/>传统的解决方案是寻找参数高效（Parameter-Efficient）的迁移学习方法，即微调的时候不改变全部的参数，只去改变部分的参数就好了。能尽可能的少更新参数并尽可能保证任务性能，那也不错。<br/><font style="background-color:rgba(183,237,177,0.8);">但</font><font style="background-color:rgba(183,237,177,0.8);">OpenAI</font><font style="background-color:rgba(183,237,177,0.8);">团队不会只局限于此。他们的梦想是实现AGI，实现通用的、类似人的智能。人类可不会只擅长某一个具体的下游任务，参数高效的</font><font style="background-color:rgba(183,237,177,0.8);">迁移学习</font><font style="background-color:rgba(183,237,177,0.8);">再高效，毕竟也需要人为对任务做划分。</font>因此，OpenAI更关注另一个的解决方案：能不能我们去把它应用于任何下游任务时，都不要去改模型的参数权重了，而是只需要用自然语言给模型一些提示词就可以？这就是Prompt。<br/>**写这么多是希望大家可以知道：Prompt工程不只是工程师们的异想天开：这是让大力出奇迹的超大型模型能在多种场合都有所作为的前置要件，也是通往AGI的必由之路。** |

## <font style="color:rgb(36,91,219);">3 </font>**前Prompt时代的尝试：参数高效学习 Parameter-Efficient ****Transfer Learning**
[<font style="color:rgb(36,91,219);">【arxiv】Parameter-Efficient Transfer Learning for NLP</font>](https://arxiv.org/pdf/1902.00751.pdf)

[<font style="color:rgb(36,91,219);">参数高效微调指南</font>](https://zhuanlan.zhihu.com/p/619583361) By [<font style="color:rgb(36,91,219);">TimsonShi</font>](https://www.zhihu.com/people/timsonshi)

#### <font style="color:rgb(36,91,219);">3.1.1 </font>**参数高效的定义**
+ **<font style="background-color:rgba(186,206,253,0.7);">全面微调：</font>**<font style="background-color:rgba(186,206,253,0.7);">做针对下游任务的Fine-tuning时，更新模型的所有参数。</font>这不可避免地导致模型对小的目标数据集过度拟合，继而在微调后不能用于其他任务。
+ **<font style="background-color:rgba(186,206,253,0.7);">参数高效微调（Parameter-Efficient Fine-tuning，PEFT）</font>**<font style="background-color:rgba(186,206,253,0.7);">：做针对下游任务的Fine-tuning时，不更新模型全部的参数。</font><font style="background-color:rgba(183,237,177,0.8);">我们可能选择性的只更新模型最上面的几层权重，也可能只去更新偏置而不去改变</font><font style="background-color:rgba(183,237,177,0.8);">神经元</font><font style="background-color:rgba(183,237,177,0.8);">之间的连接强弱</font>。我们的目的是在尽可能少更新参数的情况下尽可能保证模型的下游任务的性能。

#### <font style="color:rgb(36,91,219);">3.1.2 </font>**部分参数微调：选择法Selective Method**
为了解决巨大的预训练模型的Fine-tune问题，研究人员们首先提出了部分参数微调/冻结部分参数的方法。

+ **最早的一批工作是只微调网络的最上面几层。**
+ **后来人们认为可以根据人的经验和推理去微调网络中和下游任务最相关的部分。**
1. 首先，我们人类对模型的参数分布是有先验知识的<font style="background-color:rgba(183,237,177,0.8);">。例如学完了第10章，我们就应该知道，Encoder部分负责编码语言为高维的向量，而Decoder负责生成目标的句子。</font>
2. <font style="background-color:rgba(254,212,164,0.8);">有了类似这样的基于先验知识的假设之后，在微调模型的参数时，我们就可以更新和目标任务最相关的那部分</font>。例如，<font style="background-color:rgba(183,237,177,0.8);">如果要把一个用于生成摘要的Transformer转变为生成原文的Paraphrasing，那么可能我们就只需要改Decoder的参数就行了，而不去改Encoder。</font>
+ **更极端的做法是只微调模型偏置项或者某些行。**
+ **最极端的版本可能是稀疏地更新模型，无视模型结构，只更新某些参数。**

#### <font style="color:rgb(36,91,219);">3.1.3 </font>**使用额外的参数增强现有预训练模型：附加法Additive Method**
**<font style="background-color:rgba(186,206,253,0.7);">附加法的主要思路是使用额外参数或层增强现有预训练模型，它只训练这些新加入的参数。</font>**目前这是最大、最广为应用的PEFT方法。附加法的实现方式为适配器（这里先不提软提示）。

**<font style="color:rgb(216,57,49);">适配器 Adapter</font>**

**<font style="background-color:rgba(186,206,253,0.7);">简单来说，就是在Transformer子层后面加入小的全连接网络。</font>**

| <font style="color:rgb(143,149,158);">在上述”部分参数微调“方法的基础之上，研究人员提出了Adapter方法，通过添加一个灵活的即插即用的可训练适配模块(Adaper Module)，我们可以改变模型某一层（或某几层）的数据分布，从而让模型可以适用于各种各样的任务和领域。典型的做法就是每一任务或者每一领域对应了一个Adapter Module，训练的时候只更新对应任务Adapter的参数，推理的时候激活对应任务/领域的Adapter，其它任务/领域的Adapter直接忽视。和”部分参数微调“方法相比，Adapter方法的优势有（1）更轻量级（2）同样比例的参数效果更好。</font> |
| :--- |


#### <font style="color:rgb(36,91,219);">3.1.4 </font>**基于重参数化的方法 Reparametrization-based PEFT**
[<font style="color:rgb(36,91,219);">【arxiv】INTRINSIC DIMENSIONALITY EXPLAINS THE EFFECTIVENESS OF LANGUAGE MODEL FINE-TUNING</font>](https://arxiv.org/pdf/2012.13255.pdf)

基于重参数化的PEFT方法（reparametrization-based PEFT）利用的是低秩矩阵表示来减少可训练参数数量。**<font style="background-color:rgba(254,212,164,0.8);">目前使用最多的基于重参数化的方法是低秩适配（Low-Rank Adaptation, </font>****<font style="background-color:rgba(254,212,164,0.8);">LoRA</font>****<font style="background-color:rgba(254,212,164,0.8);">）</font>**。<font style="background-color:rgba(255,246,122,0.8);">LoRA这个名儿很多读者，尤其是关注Diffusion算法的读者肯定不会陌生！</font>在很多应用中，Low-Rank Adaptation技术已经被证明非常有效。例如，在图像处理领域，利用低秩结构可以实现图像去噪、图像复原、图像分割等任务。在推荐系统中，Low-Rank Adaptation技术可以提高推荐算法的准确性和鲁棒性。<font style="background-color:rgba(251,191,188,0.8);">不过我还没有想好要不要在这篇文章里介绍LoRA。</font>

#### <font style="color:rgb(36,91,219);">3.1.5 </font>**对上述方法的评价**
在12.3.2.2～12.3.2.4中，我们提到了很多参数高效的学习方法，他们用于解决LLM变得越来越大所以难以训练的问题。<font style="background-color:rgba(251,191,188,0.8);">但是，我们可以看到，以上方法都是基于”预训练-微调“的</font><font style="background-color:rgba(251,191,188,0.8);">范式</font><font style="background-color:rgba(251,191,188,0.8);">的方法，无论多么轻量级，每个任务都还是有一套特定的参数（即使大部分参数可以共享）。</font>

| <font style="color:rgb(143,149,158);">说到这里，大多数人其实并没有意识到，</font>**<u><font style="color:rgb(216,57,49);">它的致命缺点正是：任务本身需要人为进行定义</font></u>**<font style="color:rgb(143,149,158);">。但是现实生活中的知识，并不是完全地按照任务进行分类的，现实中大多数任务会涉及到多个任务的能力: 比如一个中国人阅读了一篇英文的文章，最后用中文写了个总结 --- 这就涉及到 翻译+总结 两个任务。</font>**<font style="color:rgb(216,57,49);">而Prompting可以做到模糊任务的界限---</font>****<u><font style="color:rgb(216,57,49);">不需要人为对任务进行划分</font></u>****<font style="color:rgb(216,57,49);">，相反，任务的描述会作为输入的一部分直接输入</font>****<font style="color:rgb(216,57,49);">预训练模型</font>****<font style="color:rgb(216,57,49);">。</font>**<br/><font style="color:rgb(143,149,158);">这其实就是为什么Prompting</font><font style="color:rgb(143,149,158);">范式</font><font style="color:rgb(143,149,158);">是“通往真正大一统语言模型的关键一步”。</font> |

## <font style="color:rgb(36,91,219);">4 </font>**定义Prompting：通往真正大一统语言模型的关键一步**

### <font style="color:rgb(36,91,219);">4.1 </font>_**<font style="color:rgb(216,57,49);">Prompting / Prompt Learning的定义</font>**_
<font style="background-color:rgba(186,206,253,0.7);">读完</font>[_<font style="color:rgb(36,91,219);background-color:rgba(186,206,253,0.7);">12.2.2.1</font>_](https://s3tlxskbq3.feishu.cn/docx/NyPqdCKraoXz9gxNVCfcIFdnnAc#KUW4dyCAyo442wx04r0cAT6Fnvd)<font style="background-color:rgba(186,206,253,0.7);">后，我们应该能够理解，Prompt的目的是将Fine-tuning的下游任务目标转换为Pre-training的任务，</font><font style="background-color:rgba(183,237,177,0.8);">（即各种子任务都可以用基于下一词预测的Question Answering来表达）</font><font style="background-color:rgba(186,206,253,0.7);">；且与此同时，我们不可以给下游任务构建特定的输入结构，不能添加额外的特殊符号。</font>

<font style="background-color:rgba(255,246,122,0.8);">提示学习这种方式拉近了测试分布与预训练分布的距离，进而可以利用大规模预训练语言模型在预训练过程中习得的强大语言建模能力，使其不经过微调就可以在各种下游任务上取得很好的结果。</font>

采用Prompt的范式之后，Pre-train，Fine-tune的范式变成了Pre-train，prompt & predict。

| <font style="color:rgb(143,149,158);">融入了Prompt的新模式大致可以归纳成“pre-train, prompt, and predict”，在该模式中，下游任务被重新调整成</font><font style="color:rgb(143,149,158);">类似预</font><font style="color:rgb(143,149,158);">训练任务的形式。例如，对于一个预训练的</font><font style="color:rgb(143,149,158);">GPT</font><font style="color:rgb(143,149,158);">，我们在文本情感分类任务中，</font><font style="color:rgb(143,149,158);background-color:rgba(183,237,177,0.8);">对于 "I love this movie." 这句输入，可以在后面加上prompt "The movie is ___" 这样的形式，然后让预训练语言模型用表示情感的答案填空如 "great"、"fantastic" 等等，最后再将该答案转化成情感分类的标签</font>**<font style="color:rgb(143,149,158);">，</font>****<font style="color:rgb(216,57,49);">这样一来，通过选取合适的prompt，我们可以控制模型预测输出，从而让一个完全无监督训练的PLM可以被用来解决各种各样的下游任务</font>**<font style="color:rgb(143,149,158);">。</font><br/><font style="color:rgb(143,149,158);">——</font>[<font style="color:rgb(36,91,219);">【知乎】NLP新宠——浅谈Prompt的前世今生</font>](https://zhuanlan.zhihu.com/p/399295895)<font style="color:rgb(143,149,158);"> By </font>[<font style="color:rgb(36,91,219);">AI Box专栏</font>](https://www.zhihu.com/people/dou-hong-jian-44)<font style="color:rgb(143,149,158);">，作者：闵映乾@RUC </font> |
| :--- |


**在数学上区分fine-tune和prompt：**

+ 我们知道，<font style="background-color:rgba(255,246,122,0.8);">Fine-tuning的过程是一个有</font><font style="background-color:rgba(255,246,122,0.8);">监督学习</font><font style="background-color:rgba(255,246,122,0.8);">的过程</font>。基于输入，以为参数的模型会预测输出的概率分布：，而后这个概率分布再会和我们标注的输出做比较，计算损失函数。
+ 相比之下，<font style="background-color:rgba(254,212,164,0.8);">Prompting的目的就是避开用标注数据做有监督的微调</font>。因此，是没有输入输出pair（与）的。在数学上，它是这么做的：基于我们输入的input，模型会建模的概率分布:_，_而后用这个的概率分布再去预测**<font style="background-color:rgba(255,246,122,0.8);">（Predict）</font>**模型的输出y。
+ 这样说话可能会比较Confusing。<font style="background-color:rgba(183,237,177,0.8);">更清晰的说法我觉得是，模型能够做到理解我们的意图，并把我们输入的稍加改造</font>。被改造后的，姑且称为吧，会是一个模型更熟悉的东西，模型基于去预测y。
+ **<font style="background-color:rgba(254,212,164,0.8);">可以看到，上述的过程是无监督的，而基于去预测y是语言模型本身就具有的能力。因此，关键在于怎么去设计把输入的改造成的这个机制。</font>**

### <font style="color:rgb(36,91,219);">4.2 </font>_**<font style="color:rgb(216,57,49);">Prompt最早还不叫Prompt，它只是一种模版（Template）</font>**_**<font style="color:rgb(216,57,49);">。</font>**
<font style="background-color:rgba(251,191,188,0.8);">2.2.1提到，关键在于怎么去设计把输入的改造成的这个机制。这就让人不禁想到一个方法——用模版。</font>

其实Prompt最早不叫这个名，他无非是一种模版。_<font style="background-color:rgba(183,237,177,0.8);">所以我们可以看到，整个提出GPT-3的论文</font>_[_<font style="color:rgb(36,91,219);background-color:rgba(183,237,177,0.8);">Language Models are Few-Shot Learners</font>_](https://arxiv.org/pdf/2005.14165.pdf)_<font style="background-color:rgba(183,237,177,0.8);">（2020.5）里，Prompt这个词只出现了27词。但到了InstructGPT（2022.3）的时候，Prompt在论文中的</font>__<font style="background-color:rgba(183,237,177,0.8);">词频</font>__<font style="background-color:rgba(183,237,177,0.8);">就超过300次了。</font>_

<font style="background-color:rgba(186,206,253,0.7);">Prompt最早是研究者们为了下游任务设计出来的一种输入形式或模板，它蕴含了不同的下游任务的信息，且输入形式和大语言模型进行预训练时的输入很像</font>，<font style="background-color:rgba(255,246,122,0.8);">因此能够帮助预训练语言模型“回忆”起自己在预训练时“学习”到的东西。</font>

| **<font style="color:rgb(216,57,49);background-color:rgba(186,206,253,0.7);">回答工程 Answer Engineering</font>****<font style="background-color:rgba(186,206,253,0.7);">：</font>**<font style="background-color:rgba(186,206,253,0.7);">指的是设计回答，以让z填充[Z]的机制的工程。</font><br/>1、这里的<font style="background-color:rgba(255,246,122,0.8);">可以是一个有限的选择，</font><font style="background-color:rgba(183,237,177,0.8);">尤其是在分类任务中，例如我们之前做情感分类时的崩、典、急、孝、麻五种。</font><font style="background-color:rgba(255,246,122,0.8);">也可以生成任何文本用于填充[Z]，尤其是在生成式任务中</font><font style="background-color:rgba(183,237,177,0.8);">（like </font><font style="background-color:rgba(183,237,177,0.8);">GPT</font><font style="background-color:rgba(183,237,177,0.8);">）。</font><br/>2、语言模型可以做两件事。首先是它它老本行：判断一整句话Make sense的概率。这个功能可以用于给句子打分。例如，我们在填充[Z]时，可以把崩、典、急、孝、麻五种都尝试一遍，对每一个都打分，然后选分数最高的一个。<br/>3、其次是下一词预测，它可以用来生成任意的填在[Z]里的内容，而不需要人类去提前规制。 |

| :---: | :---: | :---: | :---: |


| 但手动设计模版这件事还是存在很多局限性：<font style="color:rgb(36,91,219);">首先，模版很难设计，背后需要工程经验甚至天马行空的沾点艺术的灵感，颇有些以往的“</font><font style="color:rgb(36,91,219);">专家系统</font><font style="color:rgb(36,91,219);">”的味道</font>，从历史发展的角度看，这注定会被淘汰；其次，研究机器学习的人懂个屁的机器，<font style="color:rgb(36,91,219);">符合人类直觉的提示词不一定是最能激发机器的潜能的。Optimal prompts可能是在人类看来很诡异的token组合，只靠人类自己拍脑袋的话，一辈子都想不出来</font>。 |
| :--- |


#### <font style="color:rgb(36,91,219);">5.1.2 </font>**参数化Prompt/自动 Prompt**
<font style="color:rgb(216,57,49);">#哼哼，我们都有GPT-3这么牛逼的东西了，为什么不干脆让模版也由机器来写呢？</font>

+ 于是，就有了**<font style="background-color:rgba(186,206,253,0.7);">自动模版学习（Automated Template Learning）</font>**<font style="background-color:rgba(186,206,253,0.7);">，</font><font style="color:rgb(36,91,219);background-color:rgba(186,206,253,0.7);">也就是说不再由人类拍脑袋来设计Template，Template也由机器来自动生成，机器决定Template有哪些文字，</font><font style="color:rgb(36,91,219);background-color:rgba(186,206,253,0.7);">input</font><font style="color:rgb(36,91,219);background-color:rgba(186,206,253,0.7);"> slot在哪，answer slot在哪</font><font style="background-color:rgba(186,206,253,0.7);">。</font>
+ 一旦把格局打开，让语言模型去写模版后，就有了许多新的可能性：<font style="background-color:rgba(255,246,122,0.8);">首先是可以发挥</font><font style="background-color:rgba(255,246,122,0.8);">神经网络</font><font style="background-color:rgba(255,246,122,0.8);">的优势，去做试错学习，不断挖掘、迭代和优化，让性能不断变好</font>。<font style="background-color:rgba(183,237,177,0.8);">其次是可以发挥人工智能具有的自动化的能力，例如实现为每个输入生成一个自定义模板，而不是一个模版走天下</font>。从而，自动模版学习产生了两种分类方式：
    - <font style="background-color:rgba(186,206,253,0.7);">离散型提示（discrete prompts）和连续型提示（continuous prompts）。前者就是文本构成的模版，后者则还是在LLM嵌入层的向量空间里的向量组合。</font>
    - <font style="background-color:rgba(186,206,253,0.7);">静态提示Static Prompt和动态提示Dynamic Prompt。静态的Prompt对每个输入使用基本相同的提示模板，而动态的为每个输入生成一个自定义模板。</font>静态和动态策略都被用于不同种类的离散和连续提示。

| <font style="color:rgb(143,149,158);"> In particular, the automatically induced prompts can be further separated into discrete prompts, where the prompt is an actual text string, and continuous prompts, where the prompt is instead described directly in the embedding space of the underlying LM。</font> |
| :--- |


### <font style="color:rgb(36,91,219);">5.2 </font>**离散提示/硬提示 Discrete Prompt a.k.a Hard Prompt**
**<font style="color:rgb(216,57,49);">在自动模版学习中，离散提示或者硬提示，就是生成以自然语言的文本形式存在的提示模版的意思。</font>**

<font style="background-color:rgba(183,237,177,0.8);">叫这个名字是因为自然语言本质上是一个个one-hot向量的token构成的序列，处在一个离散的空间。相比之下，以稠密向量的形式在嵌入层存在的提示就是连续的。</font>_<font style="background-color:rgba(222,224,227,0.8);">（Works on discovering discrete prompts (a.k.a hard prompts) automatically search for templates described in a discrete space, usually corresponding to natural language phrases）</font>_。

它主要有如下的生成方式：

1. **Prompt Mining 提示挖掘**：通过分析大量的文本数据，识别出其中的关键词、短语和句子，并将其组合成一系列简洁而有效的“prompt”作为自然语言模型的输入。
2. **Gradient-based Search 基于梯度的搜索**：梯度下降/上升是一种寻找极小值/极大值的方法，自然可以用这种方法来寻找最优的prompt。<font style="background-color:rgba(255,246,122,0.8);">由于离散领域中没有可微函数，因此需要对梯度下降算法进行一些改进，导致基于梯度的搜索的硬提示生成比较复杂</font>。
3. **<font style="background-color:rgba(186,206,253,0.7);">Prompt Generation 提示词生成：</font>**<font style="background-color:rgba(186,206,253,0.7);">将提示词的生成视为一项文本生成任务，并使用标准的Generative自然语言模型来执行这项任务。例如基于seq2seq架构的T5模型</font>

### <font style="color:rgb(36,91,219);">5.3 </font>**连续提示/软提示 Continuous Prompt a.k.a Soft Prompt**
<font style="color:rgb(216,57,49);">#等等，我们真的在乎模版是不是“自然语言”构成的吗？——你的下一句提示词，又何必是提示词！</font>

| <font style="color:rgb(143,149,158);">对于一些软提示方法，例如Prefix-Tuning和P-tuning，他们重新审视了关于模版的定义，放弃了“模版由自然语言构成”这一常规要求，从而将模版的构建转化为连续参数优化问题，虽然简单，但却有效。</font><br/><font style="color:rgb(143,149,158);">——</font>[<font style="color:rgb(36,91,219);">P-tuning:自动构建模版，释放语言模型潜能 - 科学空间|Scientific Spaces</font>](https://spaces.ac.cn/archives/8295/comment-page-1)<font style="color:rgb(143,149,158);"> By 苏剑林大佬</font> |
| :--- |


| <font style="background-color:rgba(255,246,122,0.8);">因为构建提示的目的是找到一种能让LM有效执行任务的方法，而不是供人使用，所以没有必要将提示限定为人类可理解的自然语言。</font>正因如此，学者们又提出了连续提示（又称软提示）的方法，**直接在模型的嵌入空间中进行提示。**<br/><font style="background-color:rgba(183,237,177,0.8);">（说是这么说，但实际操作起来其实就是冻结模型的大部分参数，而只去fine-tune一部分代表了下游任务的参数，这部分没有被冻结的参数就是软提示）</font><br/>Note：这一部分的数学推理如果要写出来会非常复杂，不符合入门文档的定位，所以基本上是在文字建模。论文原文的地址我基本都有放出来，感兴趣or功底好的朋友们可以去学。 |
| :--- |


#### <font style="color:rgb(36,91,219);">5.3.1 </font>**软提示为我们带来了什么：Template的的嵌入向量不再一定是自然语言的词嵌入**
_<font style="background-color:rgba(186,206,253,0.7);">连续 Prompt 允许使用任意词向量作为模板词的表示，这些构成Template的稠密向量不必来自于自然语言的词汇表中，可以不对应任何一个词典里的Token。</font>_

这个限制的松散有以下几个意义：

1. **更灵活的模板表示方式：**<font style="background-color:rgba(255,246,122,0.8);">在某些任务中，自然语言词汇表中的词向量可能无法准确地表示模板中的单词。</font>例如，对于一些特定的领域或术语，自然语言词汇表中可能没有对应的词汇，此时使用自然语言词汇表中的词向量表示模板中的单词可能会导致模板的表示不准确，从而影响模型的性能。因此，松散这个限制可以使得模板的表示更加灵活，可以更好地适应不同的任务和场景。
2. **更广泛的应用场景：**松散这个限制可以使得模板可以适用于更广泛的应用场景。<font style="background-color:rgba(183,237,177,0.8);">例如，对于一些非自然语言的任务，例如代码生成、机器翻译等，使用自然语言词汇表中的词向量来表示模板中的单词可能没有意义</font>，因为这些任务需要的是代码或其他非自然语言的表示方式。

#### <font style="color:rgb(36,91,219);">5.3.2 </font>**软提示为我们带来了什么：取消了模板由预训练的LM的参数决定的限制。**
模板不再受预训练语言模型参数的参数化限制的意义在于，现在我们可以使用独立的模板参数来定义模板，而不需要依赖预训练语言模型的参数。

这个意义主要有以下几点：

1. **更灵活的模板表示方式：**<font style="background-color:rgba(255,246,122,0.8);">在以前的方法中，模板的表示是由预训练语言模型的参数来决定的。</font><font style="color:rgb(36,91,219);">这个限制会导致模板只能使用预训练模型中定义的参数，因此限制了模板的灵活性。</font>而现在，模板不再受预训练模型的限制，可以根据具体任务的需求，定义适合该任务的模板参数，从而提高模板的灵活性和适用性。
2. **更精细的模板调整（Prompt-tuning）：**

| 一旦将模版从离散的自然语言变成了连续的参数（稠密的嵌入向量），我们就可以用随机梯度下降等方式去优化它。<br/><font style="background-color:rgba(255,246,122,0.8);">使用独立的模板参数可以让我们更精细地调整模板</font>，<font style="background-color:rgba(254,212,164,0.8);">只需要精调模版的参数，而不需要去改变整个预训练大语言模型。</font>这就引申出了Prompt-Tuning的概念：**<font style="background-color:rgba(186,206,253,0.7);">Prompt tuning通常指微调模板中的参数，以适应特定的下游任务。</font>**在Prompt tuning中，整个预训练语言模型通常不会被微调，而只有模板的参数会被微调。 |
| :--- |


具体而言，Prompt tuning的目标是通过微调模板的参数，使得模板能够更好地与下游任务的输入相匹配，从而提高下游任务的性能。通常情况下，模板中的参数是在预训练模型的基础上学习得到的，因此模板的参数微调相当于是在原始的预训练模型上微调得到的模板。因此，<font style="background-color:rgba(255,246,122,0.8);">尽管Prompt-tuning让我们不再需要去更改整个预训练LLM的参数，省下了大量功夫，但在微调模板时，预训练模型的知识和能力仍然发挥了重要作用</font>。

#### <font style="color:rgb(36,91,219);">5.3.3 </font>**软提示的生成方法：从Prefix-Tuning到Prompt Tuning**
<font style="background-color:rgba(254,212,164,0.8);">1、软提示的第一阶段：Prefix-Tuning，</font>_**<font style="background-color:rgba(254,212,164,0.8);">2021.1</font>**_

[<font style="color:rgb(36,91,219);">【Arxiv】Prefix-Tuning: Optimizing Continuous Prompts for Generation</font>](https://arxiv.org/abs/2101.00190)

| **<font style="background-color:rgba(186,206,253,0.7);">Prefix-Tuning（前缀微调）</font>**<font style="background-color:rgba(186,206,253,0.7);">是一种将连续的特定任务向量序列预加到输入之前的方法，通过在模型的输入前添加一个可训练的前缀（prefix），来调整模型的行为。</font><br/>参考右图，**<font style="background-color:rgba(251,191,188,0.8);">在Prefix Tuning中，模型的结构被略微的调整，它在input和每个hiddern layer前都加入了一个参数可调的前缀。</font>**前缀是可训练的，而后缀（预训练模型原有的结构）的参数通常是冻结的。<br/>Prefix Tuning与传统的Fine-tuning方法不同，它只需要微调前缀的参数，而不需要微调整个模型。<font style="background-color:rgba(255,246,122,0.8);">因此，它可以被看作是一种更轻量级的Fine-tuning方法。</font> | ![1758770987736-174f4f5b-3288-4bbd-aeb1-6fe324a79566.png](./img/XQIE7PepeTkMUeSU/1758770987736-174f4f5b-3288-4bbd-aeb1-6fe324a79566-229834.png) |
| :--- | :---: |


为什么说这个方法其实就是一种软提示呢？这是因为，<font style="background-color:rgba(183,237,177,0.8);">前缀的那些稠密的向量们（我们姑且称之为任务向量），它其实就是一种Prompt，意图是告诉模型现在该去做什么任务了，只不过用的不是自然语言，而是我们人类看不懂的一大串数字而已</font>。<font style="background-color:rgba(255,246,122,0.8);">它其实和前面参数高效微调PEFT中提到的</font>[<font style="color:rgb(36,91,219);background-color:rgba(255,246,122,0.8);">Adapter</font>](https://s3tlxskbq3.feishu.cn/docx/NyPqdCKraoXz9gxNVCfcIFdnnAc#QQowdqICKoSqeQxKDZKcY6zXndb)<font style="background-color:rgba(255,246,122,0.8);">的思路很像，都是增加额外参数的思路；但它不在模型的最后一层做一个全连接，而是在模型的嵌入层的时候就把一段特定的任务向量拼接给输入的词序列</font>。

<font style="background-color:rgba(254,212,164,0.8);">2、对前缀精调的第一次简化：P-Tuning（ Hard-Soft Prompt Hybrid Tuning，软硬混合的Tuning）</font>_**<font style="background-color:rgba(254,212,164,0.8);">2021.3</font>**_

[<font style="color:rgb(36,91,219);">【Arxiv】GPT Understands, Too</font>](https://arxiv.org/abs/2103.10385)（P-Tuning V1）

[<font style="color:rgb(36,91,219);">【arxiv】P-Tuning v2: Prompt Tuning Can Be Comparable to Fine-tuning Universally Across Scales and Tasks</font>](https://arxiv.org/abs/2110.07602)（P-Tuning V2）

| <font style="color:rgb(143,149,158);">最近Arxiv上的论文</font>[<font style="color:rgb(36,91,219);">《GPT Understands, Too》</font>](https://arxiv.org/abs/2103.10385)<font style="color:rgb(143,149,158);">提出了名为P-tuning的方法，</font>**<font style="color:rgb(216,57,49);">成功地实现了模版的自动构建</font>**<font style="color:rgb(143,149,158);">。不仅如此，借助P-tuning，GPT在SuperGLUE上的成绩首次超过了同等级别的BERT模型，</font>**<font style="color:rgb(216,57,49);">这颠覆了一直以来“GPT不擅长NLU”的结论，也是该论文命名的缘由</font>**<font style="color:rgb(143,149,158);">。</font><br/><font style="color:rgb(143,149,158);">——</font>[<font style="color:rgb(36,91,219);">P-tuning:自动构建模版，释放语言模型潜能 - 科学空间|Scientific Spaces</font>](https://spaces.ac.cn/archives/8295/comment-page-1)<font style="color:rgb(143,149,158);"> By 苏剑林大佬</font> |
| :--- |


Instead of using a purely learnable prompt template, hard-soft hybrid tuning methods insert some tunable embeddings into a hard prompt template. 

| <font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">简言之，软硬混合的提示调优指的是在离散的硬提示（构成的嵌入张量）中插入一些可以微调的任务嵌入。</font> |
| :--- |


P-tuning，即通过在嵌入输入中插入可训练、微调的变量来学习连续的提示语。

![1758770987681-96957f7b-7eaf-4f1f-8462-91ef2b4eb232.png](./img/XQIE7PepeTkMUeSU/1758770987681-96957f7b-7eaf-4f1f-8462-91ef2b4eb232-421163.png)

<font style="background-color:rgba(255,246,122,0.8);">具体的，P-Tuning的运作原理大概可以归纳如下：</font>

1. 输入一个句子，以及预先设计的一个离散的模板。以输入“<font style="background-color:rgba(222,224,227,0.8);">The Disney film is good</font>!”、模版：<font style="background-color:rgba(222,224,227,0.8);">[X],it was [Z]</font>为例，于是会有：<font style="background-color:rgba(222,224,227,0.8);">The Disney film is good！It was [MASK].</font>；
2. 对输入的template中，挑选一个（或多个）token作为pseudo token：<font style="background-color:rgba(222,224,227,0.8);">The Disney film is good! [pseudo] was [MASK]</font>.<font style="background-color:rgba(183,237,177,0.8);">其初始化可以直接使用原本的token embedding</font>。
3. 对所有的pseudo token ，喂入一层LSTM，并获得每个pseudo token输出的隐状态向量 。
4. 将整个句子喂入GPT的embedding layer，对于pseudo token部分的token embedding，就用 来替换。最后基于这样的张量，GPT就产生对应的输出。

<font style="background-color:rgba(254,212,164,0.8);">3、对P-Tuning的进一步简化Prompt-Tuning </font>_**<font style="background-color:rgba(254,212,164,0.8);">2021.4/2021.8</font>**_

[<font style="color:rgb(36,91,219);">【arxiv】The Power of Scale for Parameter-Efficient Prompt Tuning</font>](https://arxiv.org/abs/2104.08691)

| _**<font style="color:rgb(216,57,49);">We freeze the entire pre-trained model and only allow an additional k tunable tokens per downstream task to be prepended to the input text. </font>**_ |
| :--- |


+ 在GPT-3中，Prompt Token 是模型的嵌入表(Embedding Table)的一部分，因此受模型的冻结参数决定。由于参数是冻结的，所以找最优的Prompt一般需要人为搜索或者使用不可微自动化搜索方法（<font style="background-color:rgba(251,191,188,0.8);">硬提示的问题</font>）
+ Prompt Tuning依然冻结，但消除了提示由参数化的限制；相反，Prompt Tuning中的Prompt有自己的专用参数 ，可以通过反向传播算法更新。<font style="background-color:rgba(183,237,177,0.8);"> Prompt Design（手动设计离散的template）可以看做从冻结嵌入的固定词汇表中选择Prompt Token，而Prompt Tuning可以看做token已经确定，但是embedding是可以学习的。</font>
+ 相较于Prefix Tuning，<font style="background-color:rgba(254,212,164,0.8);">在Prompt-Tuning中，每个hidden layer不再需要对应添加相同长度的前缀，因此模型结构完全没有改变；只是让一些Token的Embedding参数变得可以微调，这部分参数大概占模型总参数的0.1%。</font>Prompt Tuning也因此更加灵活。

#### <font style="color:rgb(36,91,219);">5.3.4 </font>**软提示真就一定比硬提示好吗？**
答案是未必。连续提示确实有_<font style="color:rgb(36,91,219);">5.3.1</font>_和_<font style="color:rgb(36,91,219);">5.3.2</font>_中提到的好处，但它最大的问题在于，它本质上还是一种类似前prompting时代的参数高效的fine-tune方法，只不过它的Adapter并不是在整个模型的输出之前加上的一个全连接层，而是放在了模型的嵌入层。<font style="background-color:rgba(255,246,122,0.8);">于是从底层原理上，它就一样会发生类似于Fine-tuning的过拟合/任务性能不稳定等现象</font>。<font style="background-color:rgba(254,212,164,0.8);">此外，我们相信Soft prompting是参数高效、节约资源的，但不管怎么解释它依然需要靠反向传播去tune参数</font>，而且还存在伪资源节约等问题。

**<font style="background-color:rgba(251,191,188,0.8);">后面我们会看到，在2021年，软提示火了一整年，但后来谷歌依然用思维链提示，让硬提示狠狠的来了波文艺复兴。</font>**

## <font style="color:rgb(36,91,219);">6 </font>**ChatGPT/InstructGPT/GPT3.5：SFT（有监督微调）or Instruct-Tuning（指令精调），与RLHF（基于人类反馈的强化学习）（2022.3）**
论文原文：[<font style="color:rgb(36,91,219);">【Arxiv】Training language models to follow instructions with human feedback</font>](https://arxiv.org/pdf/2203.02155.pdf)

<font style="background-color:rgba(183,237,177,0.8);">根据 OpenAI 的博客，InstructGPT所用到的指令学习的方法和ChatGPT基本是一致的。所以这里就讲InstructGPT这篇文章,我们可以从中一窥ChatGPT的原理。</font>

### <font style="color:rgb(36,91,219);">6.1 </font>**摘要 Abstract**
| <font style="color:rgb(143,149,158);background-color:rgba(255,246,122,0.8);">让语言模型变得更大并不意味着它们能更好地遵循用户的意图。</font><font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">例如，大型语言模型可以产生不真实的、有毒的或根本对用户没有帮助的输出。换句话说，这些模型没有与用户</font>**<font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">“对齐”（Aligned，对齐是一个我比较喜欢的翻译）</font>**<font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">。</font><font style="color:rgb(143,149,158);">在本文中，我们展示了一个途径，通过人类反馈的微调，在广泛的任务中使语言模型与用户的意图保持一致。从一组标签员写的Prompt和通过OpenAI API提交的Prompt开始，我们收集了一组由Labeler人工去写的回答，作为我们希望的模型行为（desired model behavior）的数据集，我们使用监督学习来微调GPT-3。然后，我们收集模型输出的排名数据集，</font><font style="color:rgb(216,57,49);">我们利用人类反馈的强化学习来进一步微调这个监督模型。</font><font style="color:rgb(143,149,158);">我们把产生的模型称为InstructGPT。在人类对我们的提示分布的评估中，尽管参数少了100倍，但1.3B参数的InstructGPT模型的输出比175B的GPT-3的输出更好。此外，InstructGPT模型显示了真实性的改善和有毒输出生成的减少，同时在公共NLP数据集上，测试性能也没有降低太多。尽管InstructGPT仍然会犯一些简单的错误，但我们的结果表明，利用人类反馈进行微调是使语言模型与人类意图相一致的一个有希望的方向。</font><br/><font style="color:rgb(143,149,158);">——</font>[<font style="color:rgb(36,91,219);">【Arxiv】Training language models to follow instructions with human feedback</font>](https://arxiv.org/pdf/2203.02155.pdf) |
| :--- |


### <font style="color:rgb(36,91,219);">6.2 </font>**要解决的问题：Misaligned**
_**<font style="color:rgb(216,57,49);">大语言模型存在哪些问题：</font>**_

通过让模型更大，我们把更多的数据用Transformer压缩到了模型的权重、偏置等参数里，<font style="background-color:rgba(255,246,122,0.8);">这可能会让模型更好的在各种任务场合下实现下一词预测，但不代表可以让模型更符合用户的意愿</font>。例如：

1. **<font style="background-color:rgba(186,206,253,0.7);">Simply not useful，即讲废话</font>**。如果你问了模型一个具体的问题，但模型顾左右而言他，像写公文一样说了一堆看似有道理其实毫无价值的废话，那这个模型可能就是不够合格的。
2. **<font style="background-color:rgba(186,206,253,0.7);">Untruthful Hallucinations：错误的、AI产生的幻觉</font>**<font style="background-color:rgba(186,206,253,0.7);">（在自然语言处理中，幻觉通常被定义为“生成的内容与提供的源内容无意义或不可信）。</font>我们都知道，ChatGPT喜欢一本正经的胡说八道，一个很知名的梗就是向ChatGPT提问，林黛玉倒拔垂杨柳的事情。它回答的真的非常好（❌）

![1758770989796-6c2621bd-27c2-4595-acac-153ce9d39257.png](./img/XQIE7PepeTkMUeSU/1758770989796-6c2621bd-27c2-4595-acac-153ce9d39257-833727.png)

| <font style="color:rgb(143,149,158);background-color:rgba(254,212,164,0.8);">ChatGPT 特别擅长编造东西，因为它必须处理的数据量非常大，而且它收集单词上下文的能力非常好，这有助于它将错误信息无缝地放置到周围的文本中。</font> |
| :--- |


1. **<font style="background-color:rgba(186,206,253,0.7);">Toxic：有害的内容</font>**。例如，让GPT去帮人写假新闻、帮你大量的写垃圾邮件、写犯罪计划、写作为一个AI如何统治人类；或者让GPT输出侮辱性的、种族歧视的言论等等。

_**<font style="color:rgb(216,57,49);">这样的问题为什么会存在：Misaligned</font>**_

| An Underlying Premise：我们反思这样的问题为什么会存在时，其实首先我们已经认可了一件前提：人工智能应该输出我们人类喜欢的、符合我们人类需求的东西，而不只是“精准”的下一词预测。 |
| :--- |


| <font style="color:rgb(143,149,158);">This is because the language modeling objective used for many recent large LMs—predicting the next token on a webpage from the internet—is different from the objective “follow the user’s instructions helpfully and safely” (Radford et al., 2019; Brown et al., 2020; Fedus et al., 2021; Rae et al., 2021; Thoppilan et al., 2022). Thus, we say that the language modeling objective is misaligned. Averting these unintended behaviors is especially important for language models that are deployed and used in hundreds of applications.</font> |
| :--- |


我们每次向模型提一个问题，我们都期待模型给一个我们期待的，能够解决我们的问题而且安全无害的答案。这才是模型真正的目标函数。尽管LLM可以被以“Prompt”的输入来实现很多NLP任务，包括前面提到过的Zero-shot 0S、One-shot 1S、Few-shot FS，**<font style="background-color:rgba(254,212,164,0.8);">但它的目标函数却很简单，无非是更好的去做下一词预测：</font>**

![1758783946291-2c5c2690-667f-442d-8ddf-95ac7a7ebbbb.png](./img/XQIE7PepeTkMUeSU/1758783946291-2c5c2690-667f-442d-8ddf-95ac7a7ebbbb-803878.png)

这一目标函数当然和我们人类真正想要的helpful与safe等要求有很大的偏差。<font style="background-color:rgba(186,206,253,0.7);">由此我们定义了Misalignment:LLM在训练时的目标函数和人类的真实意图存在很大的区别，很好的下一词预测不代表很好的符合用户需求</font>。

_**<font style="color:rgb(216,57,49);">这些问题严重吗：答案是，非常严重！</font>**_

**<font style="background-color:rgba(254,212,164,0.8);">先不讲客户体验，我们直接看一些关乎一整个产品的生死存亡的问题。</font>**

+ 首先美国是一个非常讲政治正确的国家，有一堆价值观要去遵循，挑剔的很。例如，你去让LLM做下一词预测，例如，A man is ___的下一词预测，和A woman is ____的下一词预测的比较，<font style="background-color:rgba(183,237,177,0.8);">可能会非常不一样。哪怕预测下来，A man is最大可能输出Lazy，而A woman is最大可能输出Beautiful，也会有人指责你说这说明这个模型更加注重女性的外貌，还是一种Bias。总之，非常难伺候。</font>

| + 其次，舆论对于创业公司可能会好一些，但对于大公司真的是非常挑剔。参考文章：[<font style="color:rgb(36,91,219);">Google apologises for Photos app's racist blunder</font>](https://www.bbc.com/news/technology-33347866)，2015年Google上线了一款产品，可以去识别图像中的各种元素，例如Skycrapers、Cars等，结果把几个黑人识别成了Gorillas，即大猩猩。<font style="background-color:rgba(183,237,177,0.8);">媒体们知道这件事后直接炸毛了，而Google也不得不疯狂道歉，后来甚至下架了产品</font>。**<font style="background-color:rgba(222,224,227,0.8);">好好的一款产品，就这么没了，嘻嘻</font>** | ![1758770991514-ceabb455-5e55-4513-862c-24bdd1511c98.png](./img/XQIE7PepeTkMUeSU/1758770991514-ceabb455-5e55-4513-862c-24bdd1511c98-431141.png) |
| --- | :---: |


+ 中国和美国一样，也有很多不能碰的话题，而且一旦输出了非常不符合我们的核心价值观的内容、触痛到了一些不能碰的雷点，可能连产品带公司都给一次性封杀掉了。

**<font style="background-color:rgba(254,212,164,0.8);">看完生死存亡后，我们再考虑客户体验。</font>**在一些应用场合，尤其是工业级应用场合，我们肯定还是希望模型的生成具有稳定的，not helpful甚至幻觉的输出可能会降低客户的付费意愿，甚至阻碍LLM的商业化落地。因此，我们确实需要想办法来解决Misaligned这个问题。

### <font style="color:rgb(36,91,219);">6.3 </font>**解决该问题的方法：基于人类反馈的强化学习，Reinforcement Learning with Human Feedback, RLHF**
_**<font style="color:rgb(216,57,49);">先验知识：基础的强化学习知识。见第五章，</font>**_[_**<font style="color:rgb(36,91,219);">这里是链接</font>**_](https://s3tlxskbq3.feishu.cn/docx/NyPqdCKraoXz9gxNVCfcIFdnnAc#CqqQdmKS8o0yWuxc3hccrZXWnwh)_**<font style="color:rgb(216,57,49);">。</font>**_<font style="background-color:rgba(222,224,227,0.8);">OpenAI写RLHF的这个团队本身是做强化学习出家的，在这方面本来就很有一套。</font>

看完论文的摘要和12.6.2提到的问题，我们肯定对Instruct GPT的目的有一个基本的了解了，<font style="background-color:rgba(251,191,188,0.8);">即让语言模型和人类的Align做的更好一些，更helpful也更安全</font>。**<font style="background-color:rgba(254,212,164,0.8);">具体而言，他们采用的方法是RLHF，即基于人类反馈的强化学习。</font>**

![1758770991574-1e271184-f2cf-4f66-96d0-eb99e207d803.png](./img/XQIE7PepeTkMUeSU/1758770991574-1e271184-f2cf-4f66-96d0-eb99e207d803-079191.png)

虽然对于很多读者来说这都是我们第一次接触到强化学习，但RLHF具体用到的思维和方法其实都相对比较简单。回到第五章大概理解强化学习的算法后，耐心的看下去就行。

---

#### <font style="color:rgb(36,91,219);">6.3.1 </font>**<font style="background-color:rgba(186,206,253,0.7);">Step1: Supervised Fine-tuning（SFT），基于监督的微调</font>**
| <font style="color:rgb(143,149,158);">Collect demonstration data, and train a supervised policy</font> |
| :--- |


先不要去管什么Policy不Policy的，第一步其实就是一个很简单的用标注数据去给模型做微调的过程，如果没有后面两个步骤的话，这一步就根本算不上强化学习。

| 1. **<font style="color:rgb(36,91,219);">收集Prompt。</font>**Prompt有两个渠道来源：1、花钱雇人，人工来写。2、用户使用GPT产品时提交。<br/>2. **<font style="color:rgb(36,91,219);">对于收集来的Prompt，人工的给它写Output。</font>**<font style="background-color:rgba(186,206,253,0.7);">人工给它写的output（OpenAI管它叫做</font>**<font style="background-color:rgba(186,206,253,0.7);">Demonstration Data or Labeler Demonstration</font>**<font style="background-color:rgba(186,206,253,0.7);">）</font>自然得是desired output，如果模型能一直输出这种水平的答案那是最好。<br/>3. **<font style="color:rgb(36,91,219);">通过第一和第二步，其实我们就得到了一个标注数据集</font>**。<font style="background-color:rgba(254,212,164,0.8);">利用Prompt（输入）+Labeler Demonstration（标准输出），我们就可以用Fine-Tune的范式去微调GPT</font>。 | ![1758770991707-d4b275b8-67f0-4b01-9daf-386c6c36d77d.png](./img/XQIE7PepeTkMUeSU/1758770991707-d4b275b8-67f0-4b01-9daf-386c6c36d77d-337117.png) |
| --- | :---: |


<font style="background-color:rgba(186,206,253,0.7);">OpenAI把上述的这个微调GPT-3的流程称为</font>**<font style="background-color:rgba(186,206,253,0.7);">Supervised Fine-tuning，SFT</font>**。原理上，它和微调别的东西其实没有什么区别。

_**<font style="color:rgb(36,91,219);">#SFT又称Instruction-Tuning（指令精调）。它是我们通往ChatGPT之路的第二块拼图。</font>**_

_**<font style="color:rgb(216,57,49);">那么它和强化学习有什么关系呢？一直用大量的人工标注去做Fine-tune，不就好了，为什么还要去用RLHF？</font>**_

首先，可以这么去理解：

| 整个被SFT后的GPT-3其实就是一个巨大的Policy函数，这个Policy函数以用户的输入（Prompt）为自己的状态State，并在该状态下采取Action，即输出一段回答。**<font style="color:rgb(36,91,219);">这样一来，想要获取一个好的LLM模型，就不仅可以靠标注数据做Fine-tune实现梯度下降了，还可以通过策略梯度等算法去获取一个好的策略函数。</font>** |
| :--- |


_**<font style="color:rgb(216,57,49);">那么，用Labeler Demonstration不应该很香吗，为什么不全靠Fune-tune呢？</font>**_

+ <font style="background-color:rgba(255,246,122,0.8);">首先，花钱雇人去帮你写desired output还是一件非常贵的事情。</font>你得去专门的给人培训，告诉人家怎样的答案才是好的，要避开哪些不能提的东西，什么时候要直指要害而什么时候要圆滑。
+ <font style="background-color:rgba(255,246,122,0.8);">此外，自然语言的Prompt有那么多，千奇百怪，我们很难用人工写答案的方式做一个全覆盖</font>。
+ 最后，也是前面在_<font style="color:rgb(36,91,219);">12.3.1</font>_中提到的，当一个语言模型变得越来越大，找到足够的标注数据集去Tune它就会变得又贵又不可能。

**<font style="color:rgb(216,57,49);">因此，出于工作量还有成本的考虑，必须得想一个更聪明的方法，让模型和人类对齐。这个方法就是强化学习</font>**。

---

#### <font style="color:rgb(36,91,219);">6.3.2 </font>**<font style="background-color:rgba(186,206,253,0.7);">Step2: 训练一个奖励模型，Reward Model，RM</font>**
| <font style="color:rgb(143,149,158);">RM 的训练是 RLHF 区别于旧范式的开端。RM模型接收一系列文本并返回一个标量奖励，数值上对应人的偏好。其实在</font>_<font style="color:rgb(36,91,219);">6.3.1</font>_<font style="color:rgb(143,149,158);">里我们就提到过，语言模型LM的本质既可以是下一词预测，也可以是判断一句话是否Make Sense的概率；那自然，它也可以用于对一句话打分嘛。</font>**<font style="color:rgb(216,57,49);">因此，其实RM它也是一个语言模型。</font>** |
| :--- |


<font style="background-color:rgba(255,246,122,0.8);">我们知道，让人去写一段desired output作为标签的话，成本会很贵，因为它是一个生成式的任务</font>。<font style="background-color:rgba(254,212,164,0.8);">相较而言，如果人类只需要去做判别式任务，那么工作量就会减小非常多。RLHF其实就是这个思想。</font>

前面提到过了，<font style="color:rgb(36,91,219);">整个被SFT后的GPT-3其实就是一个巨大的Policy函数，这个Policy函数以用户的输入（Prompt）为自己的状态State，并在该状态下采取Action，即输出一段回答。</font><font style="background-color:rgba(222,224,227,0.8);">现在我们去回想强化学习的构成要素，即：基本元素层：【环境Environment、玩家Agent、目标Goal】；主要元素层：【状态State、行为Action、奖励Reward】；基本元素层：【策略Policy、价值Value】。</font>

| 值得注意的是，在RL中，我们可以使用奖励函数而不使用价值函数来训练策略，从而实现策略梯度算法。这种方法被称为纯粹的策略梯度方法（pure policy gradient methods）。也就是说，上面提到的东西中，Value是可以不要的。 |
| :--- |


<font style="background-color:rgba(254,212,164,0.8);">那么，为了训练出一个最佳的Policy函数，也就是能和我们的价值观对齐的LLM，目前还缺少的要素是奖励Reward。</font>

<font style="color:rgb(216,57,49);">Step2的目的就在于此，我们想要训练出来一个好的奖励模型，让他给模型输出的结果去打分。</font>

![1758770991683-25a24cc1-bb32-4dfb-8f70-aa473a80b70e.png](./img/XQIE7PepeTkMUeSU/1758770991683-25a24cc1-bb32-4dfb-8f70-aa473a80b70e-042151.png)

**训练出一个奖励模型（Reward Model，即RM）的步骤如下：**

1. **<font style="color:rgb(36,91,219);">采样一个Prompt，对模型输入该Prompt后，模型会给出多个不同的输出</font>**。

| _**<font style="color:rgb(216,57,49);">但是模型参数在推理的时候是不变的，为什么在推理的时候GPT还会有随机性？</font>**_<br/><font style="color:rgb(143,149,158);">A：这是因为在生成文本时，GPT模型会采用一种称为</font>**<font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">“采样（Sampling）”</font>**<font style="color:rgb(143,149,158);">的策略，该策略会引入一些随机性。</font><br/><font style="color:rgb(143,149,158);">具体来说，GPT模型在生成文本时，通常会根据前面的文本内容预测下一个单词或字符，</font><font style="color:rgb(143,149,158);background-color:rgba(255,246,122,0.8);">并从预测的概率分布中进行采样</font><font style="color:rgb(143,149,158);">。前面讲过Greedy Decoding和Beam Search，</font>**<font style="color:rgb(143,149,158);background-color:rgba(254,212,164,0.8);">不过ChatGPT它采用了Top-K Sampling的方法而非argmax做概率采样，即限制在预测的概率分布中只保留前K个最可能的单词或字符，然后从这K个单词或字符中随机采样</font>**<font style="color:rgb(143,149,158);">。自然的，这样的采样方法会让模型产生多种不同的输出，</font> |
| :--- |


1. **<font style="color:rgb(36,91,219);">由人工Labeler来给模型的多种不同的输出做一个排序。</font>**<font style="background-color:rgba(183,237,177,0.8);">例如，输出了A、B、C、D后，标注员认为，D>C>A=B。</font>
2. **<font style="color:rgb(36,91,219);">通过1和2，我们得到了一组数据集，这组数据集的目的是训练出一个奖励函数，即RM。</font>**具体的路径为：<font style="background-color:rgba(186,206,253,0.7);">RM也是一个神经网络，输入给RM的是模型给出的output，输出的RM对output的一个打分</font>。我们首先随机初始化Reward Model，让他去给Prompt的输出打分；而这个打分的结果应该是要符合Labeler的排序的。如果不符合的话，我们就做一个梯度下降。<font style="background-color:rgba(254,212,164,0.8);">总之，训练的目标函数就是让RM给模型的输出的打分符合Labeler给他做的一个排序</font>。

我们可以看到，Train这个Reward Model的过程本身也不是一种强化学习，而是标准的有监督学习，监督信号是我们人工标注的打分排序。只不过这个reward model在后续会被用于强化学习而已。

---

#### <font style="color:rgb(36,91,219);">6.3.3 </font>**Step3：以大模型本身为策略函数，以训练出的RM为奖励函数，通过PPO算法去微调模型**
| <font style="color:rgb(143,149,158);">Optimize a policy against the reward model using reinforcement learning.</font> |
| :--- |

## <font style="color:rgb(36,91,219);">7 </font>**思维链 Chain of Thoughts, CoT（2022.1）**
### <font style="color:rgb(36,91,219);">7.1 </font>[**<font style="color:rgb(36,91,219);">开山之作：Chain-of-Thought Prompting Elicits Reasoning in Large Language Models</font>**](https://arxiv.org/pdf/2201.11903.pdf)
![1758770992367-0f9e75d5-ab47-43a8-a6f3-8ae458af8a40.png](./img/XQIE7PepeTkMUeSU/1758770992367-0f9e75d5-ab47-43a8-a6f3-8ae458af8a40-120959.png)

| <font style="color:rgb(143,149,158);">Scaling up model size alone has not proved sufficient for achieving high performance on challenging tasks such as arithmetic, commonsense, and symbolic reasoning. ——</font>[<font style="color:rgb(36,91,219);">Self-consistency Improves Chain Of Thought Reasoning in Language Models</font>](https://arxiv.org/abs/2203.11171) |
| :--- |


思维链提示是一种针对大语言模型的Prompting方法。大语言模型彻底重塑了NLP领域的研究，<font style="background-color:rgba(255,246,122,0.8);">但是单纯的把规模搞大无法解决所有问题：大语言模型依然很难在算术、常识和符号推理等具有挑战性的任务中体现出好的性能</font>。

| 当我们做出了足够大的语言模型，把足够大的Corpus通过足够多层Transformer压缩到模型中后，**模型本身具有的“能量”可能是已经足够巨大的，足以去实现Zero-shot、few shot的预测（上下文学习）。我们要做的，就是找到更多的方法，把这些能量给激发出来**。<br/><font style="background-color:rgba(254,212,164,0.8);">正如前文中提到的，Instruct tuning和RLHF本身并没有给模型注入新的能力，所有的能力都是本来就有的；但他们很好的把模型蕴含的巨大潜能引导到了“遵循人类的指令并与人类对齐”上，于是就产生了极佳的效果</font>。**思维链也是这个思维下的产物之一：不是模型推理能力不好，而是我们的prompt不能很好的引导他们。****<font style="color:rgb(216,57,49);">以往我们在ICL中只给模型input和output的demonstration让它学习，那对于需要推理的任务，我们能不能把reasoning path也给放到demonstration里，让模型去学呢？这其实就是CoT的思想。</font>** |
| :--- |


思维链是一种特殊的In-Context Learning，而且采用的不是连续提示，而是离散提示（<font style="color:rgb(222,120,2);">在当时来看是文艺复兴，因为连续提示学习一时风头无两</font>）。它和1S、FS的提示词很像，但<font style="background-color:rgba(186,206,253,0.7);">我们除了给出Input-Output作为示范之外，还需要在输入和输出之前絮絮叨叨一阵子，给出一个推理过程，称为</font>**<font style="background-color:rgba(186,206,253,0.7);">Relationale或Reasoning Path</font>**。因此，在使用CoT技术后，我们对模型的Prompt就是一个具有逻辑推理过程的短文本了，如章节开头的图中的蓝色部分。

_<font style="background-color:rgba(183,237,177,0.8);">#2022年4月，Google发布了语言模型PaLM，它使用了Chain of Thoughts的技术后，以540B的参数规模（GPT-3的三倍左右），取得了数学问题的SOTA。</font>_

![1758770992661-cd2bde20-2101-4b9e-b0df-e1f764572f71.png](./img/XQIE7PepeTkMUeSU/1758770992661-cd2bde20-2101-4b9e-b0df-e1f764572f71-256081.png)

| <font style="background-color:rgba(255,246,122,0.8);">这篇论文相对而言比较简单，就是讲述了一个絮絮叨叨给模型讲明白逻辑的Prompt方法，没有涉及到对模型结构的调整（还没有改代码）</font>。但接下来我们就要将CoT与更多模型细节做结合了。 |
| :--- |


### <font style="color:rgb(36,91,219);">7.2 </font>**经典CoT方法之改变解码策略：**[**<font style="color:rgb(36,91,219);">Self-consistency Improves Chain Of Thought Reasoning in Language Models</font>**](https://arxiv.org/abs/2203.11171)
| <font style="color:rgb(143,149,158);">In this paper, we introduce a novel decoding strategy called self-consistency to replace the greedy decoding strategy used in chain-of-thought prompting (Wei et al., 2022), that further improves language models’ reasoning performance by a significant margin. Self-consistency leverages the intuition that complex reasoning tasks typically admit multiple reasoning paths that reach a correct answer (Stanovich & West, 2000). The more that deliberate thinking and analysis is required for a problem (Evans, 2010), the greater the diversity of reasoning paths that can recover the answer.</font><br/><font style="color:rgb(143,149,158);">自我一致性利用了这样一种直觉，即一个复杂的推理问题通常会有多种不同的思维方式来通往其唯一的正确答案，而且一个问题越复杂，潜在的逻辑链就会越多。</font> |
| :--- |


![1758770992432-7af3208b-fc28-4e93-b834-6268454f315f.png](./img/XQIE7PepeTkMUeSU/1758770992432-7af3208b-fc28-4e93-b834-6268454f315f-066014.png)

我们知道，Decoder本身是一个自回归的语言模型，语言模型在输出的时候有许多策略：

+ **Greedy Decoding Strategy，贪婪策略**。即总是输出概率最高的那一个词语。
+ **Beam-Search Strategy**。参考_<font style="color:rgb(36,91,219);">7.2.3.2</font>_。
+ **Top-k Sampling**。即在概率最高的k个词语中，基于概率做随机采样。

<font style="background-color:rgba(255,246,122,0.8);">Self-consistency就是一个基于思维链的思想，去改变解码策略的方法，其运作模式如上图所示</font>。**<font style="background-color:rgba(186,206,253,0.7);">基于我们的思维链提示的输入，模型可以用自己本来就具有的能力生成一组推理逻辑不同的Output，每个Output对应一个答案。这就像是给答案做投票一样，我们留下票数最多的答案，作为模型的最终输出。</font>**

### <font style="color:rgb(36,91,219);">7.3 </font>**名扬四海的Let's Think Step by Step: **[**<font style="color:rgb(36,91,219);">Large Language Models are Zero-Shot Reasoners</font>**](https://arxiv.org/abs/2205.11916)
<font style="background-color:rgba(255,246,122,0.8);">一般来说，既然要用思维链，那必然是One-shot或者Few-shot，因为你要给模型一个推理案例（参考下图右上角）</font>。<font style="background-color:rgba(186,206,253,0.7);">但是这篇论文指出，CoT也可以是Zero-shot：在0S CoT下，我们不需要给模型例子，只需要告诉模型你给我一步一步的思考就行</font>。

![1758770992495-bcac4d1a-c362-49fc-87c0-df4d9a693980.png](./img/XQIE7PepeTkMUeSU/1758770992495-bcac4d1a-c362-49fc-87c0-df4d9a693980-819276.png)

| <font style="color:rgb(143,149,158);">While these successes are often attributed to LLMs’ ability for few-shot learning, </font><font style="color:rgb(216,57,49);">we show that LLMs are decent zero-shot reasoners by simply adding “Let’s think step by step” before each answer.</font> |
| :--- |


只要在每个答案前加上 "Let's Think Step by Step"，LLMs就是一个体面的Zero-Shot推理者。参考上图的右下角，它是一个Zero-shot的算数应用，模型本来会输出错误的结果，但是在A：之后加上了这么一句话，模型就可以输出自己的推理过程并且输出正确的结果了。

## <font style="color:rgb(36,91,219);">8 </font>**大语言模型的涌现 Emergent Abilities：我们仍未知道那天看到的大模型会推理的原因**
[_<font style="color:rgb(36,91,219);">关于涌现能力的介绍：【arxiv】Emergent Abilities of Large Language Models</font>_](https://arxiv.org/pdf/2206.07682.pdf)

### <font style="color:rgb(36,91,219);">8.1 </font>**什么是大语言模型的涌现？——****<font style="background-color:rgba(186,206,253,0.7);">如果一种能力在较小的模型中不存在，但在较大的模型中存在，我们认为这种能力是涌现的。</font>**
| **<font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">Emergent abilities of LLMs </font>**<font style="color:rgb(143,149,158);background-color:rgba(186,206,253,0.7);">are formally defined as “the abilities that are not present in small models but arise in large models”, which is one of the most prominent features that distinguish LLMs from previous PLMs.</font><font style="color:rgb(143,149,158);"> It further introduces a notable characteristic when emergent abilities occur [31]: performance rises significantly above random when the scale reaches a certain level.</font><br/><font style="color:rgb(143,149,158);">——</font>[<font style="color:rgb(36,91,219);">【arxiv】A Survey of Large Language Models</font>](https://arxiv.org/pdf/2303.18223.pdf)<br/>![1758770992459-f97c74a1-34a1-4c65-9693-19f3544f2030.png](./img/XQIE7PepeTkMUeSU/1758770992459-f97c74a1-34a1-4c65-9693-19f3544f2030-987741.png)<br/><font style="color:rgb(143,149,158);">参考上图（来自</font>[_<font style="color:rgb(36,91,219);">【arxiv】Emergent Abilities of Large Language Models</font>_](https://arxiv.org/pdf/2206.07682.pdf)<font style="color:rgb(143,149,158);">）。涌现能力无法使用Scaling Law来从较小模型上进行预测。图中，我们让x轴是模型的参数量，y轴是某种能力的效果，</font><font style="color:rgb(143,149,158);background-color:rgba(183,237,177,0.8);">那么涌现能力在图中会有一个清晰的Pattern：在某个阈值之前的效果接近随机（把模型做大，性能也只能在一个水准上随机波动，不会偏差太多），但是超过该阈值后效果将大大高于随机</font><font style="color:rgb(143,149,158);">。</font> |
| :--- |


### <font style="color:rgb(36,91,219);">8.2 </font>**涌现是敏锐且不可预测的**
_**<font style="color:rgb(216,57,49);">涌现能力具有不可预测性：</font>**_

+ <font style="background-color:rgba(254,212,164,0.8);">我们无法预测涌现能力在模型规模达到多大时会涌现出来</font>。
+ **大多数学者在训练模型的时候，往往都没有采取最优的训练方案**_<font style="background-color:rgba(222,224,227,0.8);">（Today’s language models are likely not trained optimally (Hoffmann et al., 2022), and our understanding of how to best train models will evolve over time）</font>_**。**我们知道，Train一个Model的工程细节太多，数据来源及质量把关（例如GPT-3对CommonCrawl数据集的处理）、超参数怎么选（批大小，学习率，迭代次数，怎么做梯度下降等）、算力如何规划等等都会影响一个模型的训练结果，<font style="background-color:rgba(254,212,164,0.8);">我们也不知道怎么去Train并且Train到多大的时候会出现涌现</font>。

_**<font style="color:rgb(216,57,49);">涌现能力是敏锐的，一旦达到阈值，就会被激发出来：</font>**_

| <font style="color:rgb(143,149,158);">事实上，这些涌现能力非常令人惊讶，以至于「突然的、特定的能力扩展」已经被认为是 LLM 的两个最高定义特征之一。此外，「breakthrough capabilities」和「sharp left turns」等术语也被使用。</font><br/><font style="color:rgb(143,149,158);">——By </font>[<font style="color:rgb(36,91,219);">机器之心</font>](https://mp.weixin.qq.com/s/tt9xYESUgw3V2c4XJu5ZVw) |

### <font style="color:rgb(36,91,219);">8.3 </font>**对涌现的批评**
[<font style="color:rgb(36,91,219);">【arxiv】Are Emergent Abilities of Large Language Models a Mirage?</font>](https://arxiv.org/pdf/2304.15004.pdf)

_<font style="background-color:rgba(254,212,164,0.8);">尽管很多人通过将语言模型解释为一个复杂系统，认为LLM里的Transformer把足够多的信息在复杂系统里进行了极大程度的压缩，从而（在物理意义上）引发了相变（More is different）的角度去解释涌现，</font>__**<font style="color:rgb(216,57,49);">但也有文章批评认为涌现是一个伪概念，涌现的出现取决于我们对模型的评价指标。</font>**_

+ 我们知道，我们经常用GLUE基准数据集、HumanEval等数据集和一些评估指标去评价一个模型的能力。<font style="background-color:rgba(255,246,122,0.8);">对模型能力的评估不会是绝对客观中立的，它取决于我们的度量指标</font>。
+ **<font style="background-color:rgba(186,206,253,0.7);">斯坦福的研究者们质疑说，根本就不存在这么多奇迹，涌现的出现是度量选择的结果：</font>**章节最开始的图中忽然变得非常陡峭的曲线的出现是因为对模型的度量指标是非线性、不稳健的。更换一些更连续、平滑的指标后，涌现现象就不那么明显了，更接近线性，例如下图。

![1758770993397-7d025cfc-509f-4ddc-ba57-bb8ca6aee5c9.png](./img/XQIE7PepeTkMUeSU/1758770993397-7d025cfc-509f-4ddc-ba57-bb8ca6aee5c9-515172.png)

| <font style="color:rgb(143,149,158);">他们的怀疑基于以下观察：似乎只有在非线性或不连续地扩展任何模型的 per-token 错误率的度量下，模型才会出现涌现能力。例如，在 BIG-Bench 任务中，>92% 的涌现能力是这两个度量下出现的：</font><br/>![1758770993595-ac846b33-4401-4323-a819-84ffa95b4b7a.png](./img/XQIE7PepeTkMUeSU/1758770993595-ac846b33-4401-4323-a819-84ffa95b4b7a-888406.png)<br/><font style="color:rgb(143,149,158);">这就为 </font><font style="color:rgb(143,149,158);">LLMs</font><font style="color:rgb(143,149,158);"> 的涌现能力的起源提出了另一种解释的可能性：尽管模型族的 per-token 错误率会随着模型规模的增加进行平滑、持续且可预测地变化，但</font>**<font style="color:rgb(143,149,158);">看似尖锐和不可预测的变化可能是由研究者选择的测量方法引起的</font>**<font style="color:rgb(143,149,158);">。</font><font style="color:rgb(143,149,158);">也就是说，涌现能力可能是一种海市蜃楼，主要是由于研究者选择了一种非线性或不连续地改变 per-token 错误率的度量，部分原因是由于拥有太少的测试数据，不足以准确估计较小模型的性能（从而导致较小的模型看起来完全不能执行任务），另一部分原因是由于评估了太少的大规模模型。</font><br/><font style="color:rgb(143,149,158);">参考：</font>[<font style="color:rgb(36,91,219);">斯坦福最新研究警告：别太迷信大模型涌现能力，那是度量选择的结果</font>](https://mp.weixin.qq.com/s/tt9xYESUgw3V2c4XJu5ZVw)<font style="color:rgb(143,149,158);">，机器之心</font> |
| :--- |


| 也不要因为这篇文章就直接否定了涌现的存在，其实这篇文章也不完全严谨：<br/>首先，许多任务指标的设计本来就无法是“线性”的，对于这类任务，不应该太强人所难。<br/>其次，NLP很多任务在使用不连续的度量时，其实也是在多个样本上的平均，整体数值其实是连续的。作者也给出了两个解释，试图说明此类度量下的涌现也是海市蜃楼，但也未能严谨证明。<br/>_**<font style="color:rgb(216,57,49);">最后的最后，不管怎样，作者也没有反对模型的性能会随着参数量的提高而上升，也没有反对</font>**__**<font style="color:rgb(216,57,49);">LLM</font>**__**<font style="color:rgb(216,57,49);">具有的推理能力。其实这就足够啦</font>**_。 |
