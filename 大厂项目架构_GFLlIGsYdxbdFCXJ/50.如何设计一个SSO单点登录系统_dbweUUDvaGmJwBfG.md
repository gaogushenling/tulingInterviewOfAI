#### <font style="color:rgb(51, 51, 51);">2、用户登录状态的存储与校验</font>
<font style="color:rgb(51, 51, 51);">常见的 </font>[<font style="color:rgb(51, 51, 51);">Web 框架</font>](https://so.csdn.net/so/search?q=Web%E6%A1%86%E6%9E%B6&spm=1001.2101.3001.7020)<font style="color:rgb(51, 51, 51);">对于 Session 的实现都是生成一个 SessionId 存储在浏览器 Cookie 中。然后将 Session 内容存储在服务器端内存中。</font>

<font style="color:rgb(51, 51, 51);">用户登录成功之后，生成 AuthToken 交给客户端保存。如果是浏览器，就保存在 Cookie 中。如果是手机 App 就保存在 App 本地缓存中。本篇主要探讨基于 Web 站点的 SSO。</font>

<font style="color:rgb(51, 51, 51);">用户在浏览需要登录的页面时，客户端将 AuthToken 提交给 SSO 服务校验登录状态 / 获取用户登录信息</font>

<font style="color:rgb(51, 51, 51);">对于登录信息的存储，建议采用 Redis，使用 Redis 集群来存储登录信息，既可以保证高可用，又可以线性扩充。同时也可以让 SSO 服务满足负载均衡 / 可伸缩的需求。</font>

| **<font style="color:rgb(51, 51, 51);">对象</font>** | **<font style="color:rgb(51, 51, 51);">说明</font>** |
| :--- | :--- |
| <font style="color:rgb(51, 51, 51);">AuthToken</font> | <font style="color:rgb(51, 51, 51);">直接使用 UUID/GUID 即可，如果有验证 AuthToken 合法性需求，可以将 UserName + 时间戳加密生成，服务端解密之后验证合法性</font> |
| <font style="color:rgb(51, 51, 51);">登录信息</font> | <font style="color:rgb(51, 51, 51);">通常是将 UserId，UserName 缓存起来</font> |

#### <font style="color:rgb(51, 51, 51);">5、跨域登录、登出</font>
<font style="color:rgb(51, 51, 51);">前面提到过，核心思路是客户端存储 AuthToken，服务器端通过 Redis 存储登录信息。由于客户端是将 AuthToken 存储在 Cookie 中的。所以跨域要解决的问题，就是如何解决 Cookie 的跨域读写问题。</font>

<font style="color:rgb(51, 51, 51);">解决跨域的核心思路就是：</font>

+ <font style="color:rgb(51, 51, 51);">登录完成之后通过回调的方式，将 AuthToken 传递给主域名之外的站点，该站点自行将 AuthToken 保存在当前域下的 Cookie 中。</font>
+ <font style="color:rgb(51, 51, 51);">登出完成之后通过回调的方式，调用非主域名站点的登出页面，完成设置 Cookie 中的 AuthToken 过期的操作。</font>
